调整量表只保存本地草稿，点击下一题或最终揭晓时才记录当前数值与本题累计用时。

人物画像和分享卡均完整保留竖图。

源码维护：
main-character-test/ 是可编辑的 React 源码，public/collector.js 是真实采集脚本。
前端开发和构建需要 Node.js 22.12+，实际采集还需要 NBTI 根目录的 Node.js 接口及 MySQL。
在源码目录依次执行 npm ci、npm test、npm run build；dist/ 是源码的构建输出。
修改源码后，在 NBTI 根目录执行 npm run frontend:build。
该命令运行 scripts/build-frontend.mjs，构建源码 dist/，同步根 index.html、assets/、
collector.js、favicon.svg、最终显示题库及媒体，旧产物备份到 .local/frontend-backups/。
构建按当前 public/media/manifest.json 引用文件及二十个角色 SVG 复制资源，
题图按 public/question-art/manifest.json 复制当前 40 题的 120 张图片及清单；
不会把 public/ 中所有文件直接发布；退役素材与生成说明归档到根目录的私有
.local/retired-public/，旧前端保留在 .local/frontend-backups/，均不进入公开部署。
根服务用 data/public-assets.json 限定可公开路径；旧题库仅供后端历史数据兼容，
不显示旧问卷入口，也不允许以静态文件下载。重建后重启根服务以加载新清单。
外部 NBTI 发布脚本需同步 question-art/，并将当前题图路径加入根服务和 Nginx
公开文件清单；仅推送本 GitHub 源码仓库不会自动更新 www.nbti.cn 的生产部署。
新版 manifest 直接编入前端 JavaScript，修改媒体清单后也需重新构建。
scripts/instrument-bundle.mjs 仅保留为历史静态注入工具，当前源码构建不再使用它。

本地开发与预览：
1. 在 NBTI 根目录首次运行 npm ci，然后运行 npm run local:start。
2. 在 main-character-test/ 首次运行 npm ci，然后运行 npm run dev。
3. 构建后可运行 npm run preview；dev 和 preview 都代理本机 127.0.0.1:3000。
4. 按终端显示的地址访问；根服务提供采集 API 与 public-config.js 运行时配置。
5. 未启动根服务时只能预览页面，采集队列暂存在浏览器中，无法入库。
Windows PowerShell 可使用 npm.cmd 执行上述命令。

按原题库与 40 题完成条件解释；旧浏览器该版本待同步队列仍可补传。

其他尚未升级的旧 40 题量表实例，先执行 npm run local:stop -- -AppOnly 保留 MySQL 运行，
