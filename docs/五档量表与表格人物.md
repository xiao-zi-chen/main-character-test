# 五档量表与表格人物

本次源码把量表改为真正的五档：0、1、2、3、4，中立值为 2。标签、触摸、键盘、评分、答题采集、存储和自动化测试使用同一范围。每个维度仍抽两题，一轮共二十题。左右端点与原 A/B 方向一致，归一化得分为 0～100。

## 记录兼容与上线要求

- 新协议：`nbti-2026-10-17-scale5-sample20`；每条 `answers[].scaleValue` 必须是 0～4 的整数，其他采集字段和计时规则不变。
- 前端进度保存到 `main-character-casting:v4`，记录 `version: 4`。旧 v3 进度保留，但不恢复、不四舍五入、不转换为新回答。
- 采集队列继续保留旧 `nbti-2026-10-15-sample20` 和 `nbti-2026-10-02-scale15` 的未同步记录，原数值、协议和用时不变。旧会话不能作为五档会话继续答题。
- 外部 NBTI 后端需要先支持新协议：按版本分别验证 0～4 或 0～14，继续验证 20 题抽样、每维度两题、完成条件以及事件幂等。导出与统计也需按问卷版本解释数值。
- 本仓库没有 NBTI 服务端；本次没有修改生产数据库、数据库迁移或生产服务。不要用旧的破坏性迁移来切换量表。若服务器尚不支持新协议，新记录留在浏览器等待同步。

## 表格与人物

`视频排序(4).xlsx` 对应 17 条影片、28 个具名人物。`content/selected-films.json` 保存原姓名、顺序和备注，`content/selected-character-profiles.json` 保存逐人性格、评分画像和原片取景位置。当前目录仅包含这 28 人，全部可访问；旧的额外人物与隐藏解锁不参与本版结果。

双人物分别使用 `#/role/<人物ID>`、独立画像与性格文案；`filmId` 和 `videoId` 指向同一影片。视频使用独立的内容版本号，因此同片两人的视频 URL 完全相同。结果页列出同片人物，可直接切换。

画像来自对应原片中本人画面的裁切，未添加文字。部分背景人物在原片中较小，其特写质量仍依赖后续视频重制。`content/selected-film-import.json` 记录源文件、原片 SHA-256、取景时间、裁切范围及待修改状态。运行 `python -X utf8 scripts/build_selected_catalog.py` 可重建人物、画像和媒体清单；需要 Python、Pillow、FFmpeg。运行 `npm run export:worlds` 更新对应场景 SVG。

发布白名单仅复制当前 17 条影片、28 张人物画像、28 个场景 SVG、题图清单及当前入口文件；仓库中的旧媒体不会因为保留在磁盘上就自动重新发布。外部 NBTI/COS/Nginx 的同步和公开文件清单也需要更新，不应继续发布旧角色的视频地址。

## 题图清晰度与生成状态

当前 120 张生产题图仍是上一轮生成素材。本次在左右反应图上加入逐题匹配的物件符号与颜文字，不加说明文案；页面原题干、选项文字继续用于明确含义和无障碍访问。

`src/data/question-art-cues.js` 为全部 40 题逐项规定了更明确的动作。运行 `node scripts/export_question_clarity.mjs` 生成 `content/question-art-clarity-prompts.json`：强化人物面部、手部、关键物件和两种动作的差异，保留每题独立画风，禁止画面文字。该文件明确标为 `prepared-not-generated`，不替换现有生产来源记录。

实际重新生成 120 张图片尚未执行：当前会话没有内置生图工具，也尚未选择新的生成服务。生成后还需逐题检查动作、人物一致性、左右语义与无文字要求，再更新生产清单、内容哈希和缓存版本。
